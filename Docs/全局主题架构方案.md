# 夜航船 · 全局主题架构方案

> 交付形态：架构方案咨询（**未修改任何代码**）
> 需求：为项目添加全局主题，让用户能看见的所有界面都交由用户自定义——主题字体、界面背景、阅读背景、加载画面等
> 自定义深度：**完全自由定制**（最高自由度一档）
> 参与：齐活林（交付总监 · 汇编）｜高见远（架构）｜画意浓（设计系统）｜库有方（持久化）
> 日期：2026-11-28
> **决策更新（2026-11-28）**：用户已确认 4 项开放项——① iCloud 一期同步 `activeThemeID`、二期独立记录 + 冲突解决；② 字体仅用户从文件 App 导入；③ 开放 MeshGradient 自定义点；④ 主题文件格式为 `.yhthm`（ZIP 含资产）。已逐项细化为可实施规格，见 **§10**，并对相关章节做了同步修订。

---

## 0. 主理人结论先行

**需要改架构，但不必重写。** 现状是「静态 `Palette` + 系统自适应色 + 两套互不连通的主题体系（全局 `AppAppearance` / 阅读页 `ReaderTheme` + 自有字体体系）」。要支持完全自由定制，必须补上三层：**主题领域模型层 → 主题引擎/环境注入层 → 令牌适配层**，并把 `Palette` 从「唯一真源」降级为「内置默认主题」。

改动量级为**中大型**：全工程 `Palette.` 约 600 处、`.font(.system:)` 约 483 处、`AppBackdrop()` 约 35 处，分布在 12 个文件；但可通过「共享组件优先 + 逐文件迁移」分阶段收敛，每个阶段都能独立编译、回归。

### 三条不可突破的边界（写入产品说明）

1. **系统启动屏不可自定义**。`Info.plist` 的 `UILaunchScreen` 是系统接管的静态资源，运行时无 API，审核也不允许广告式/交互式启动页。可自定义的「加载画面」只能落在 **App 内加载态、转场、骨架屏、首次进入动画**。
2. **背景必须保持静态，但开放 MeshGradient 自定义点**。现有 `AppBackdrop` 挂载 30+ 处且刻意去掉动画保性能；本次决策**开放用户自定义 MeshGradient 的锚点与配色**，但结构里不得出现任何时间/动画字段，禁止 `repeatForever`。网格上限 5×5、解析一次并缓存，详见 §10.3。
3. **完全自由 ≠ 放弃护栏**。必须内置对比度校验、动态字体（Dynamic Type）、减弱动效、色盲友好、触控尺寸下限等护栏，避免用户配出「字看不见」的组合。

## 1. 现状诊断（基于真实代码的共识）

三位成员独立读码后的一致结论：

- **两层主题彼此独立**：界面层 `Palette`（accent/jade/gold/text/secondary/tertiary/hairline/faint/glassTint + covers，全部 `Color.adaptive(light:dark:)` 随系统明暗）+ `AppBackdrop`（3×3 MeshGradient + 两团光斑）；阅读层 `ReaderTheme` 五套（日间/羊皮纸/护眼/夜航/夜间）自带 `background/backgroundDeep/text/secondary/accent/isDark`，另有字号/字重/行距/版心。
- **持久化已有成熟惯例**：`AppStore.Snapshot` 12 分区逐分区兜底；`ReaderSnapshot`（14 项）与 `EyeCareSettings` 用 `decodeIfPresent ?? 默认` 逐字段兜底，未知枚举 `try? ... flatMap { $0 } ?? default`；坏文件改名留档、不就地覆盖；未来版本只读不写盘。
- **性能敏感点**：`SnapshotAutosaver`（零尺寸叶子观察点）避免拖字号滑块重建整个 `TabView`；阅读页 `rebuild()` 是真 CoreText 重排，不能让纯颜色变化触发。
- **字体现状**：无 `UIAppFonts` / `Font.custom`，全部系统字体；`ReaderFontDesign` 仅宋体/系统/圆体三档。
- **弹层独立宿主**：sheet / fullScreenCover 盖不住根视图的护眼层，必须各自 `.appChrome(store)` 接外观——主题环境必须照搬这一处理。
- **iCloud 现状**：`CloudSyncService` 单条 CKRecord `YeHangSnapshot` + CKAsset 全量快照，无 scope、本机优先；备份中心 `BackupScope` 三值（sources/library/preferences）。二期主题同步须另起记录类型，不塞进这条快照。

## 2. 总体架构（架构设计 · 高见远）

```mermaid
graph TD
    M[主题领域模型层<br/>ThemeConfig / 各类 Spec] --> E[主题引擎与解析器<br/>ThemeEngine：配置→当前明暗下的具体令牌]
    E --> S[主题状态与持久化层<br/>AppStore.theme + ThemeAssetStore + Snapshot 分区]
    S --> ENV[环境注入层<br/>@Environment(\.theme) ThemeTokens]
    ENV --> AD[令牌适配层<br/>Palette 兼容壳 / theme.accent / View+themeFont]
    AD --> V[业务视图层<br/>Shelf / Source / Settings / Reader / Labs ...]
    S --> ED[自定义编辑器层<br/>ThemeEditor：调色/背景/字体/加载/预设/导入导出]
    ED --> S
    S --> R[渲染器<br/>ThemeBackdrop / ThemedLoadingView]
    R --> V
    S --> SY[同步与包交换层（本次决策细化）<br/>ThemePackage(.yhthm) / ThemeSyncService(二期)]
    SY --> S
```

依赖方向：**模型层不依赖任何视图**；引擎只依赖模型；持久化只依赖模型/引擎；视图只依赖环境与适配层；编辑器只读/写主题状态，不直接触碰业务视图；同步层只与持久化层交互。

各层职责：

1. **主题领域模型层**：一套 `Codable/Sendable` 配置，表达色板覆盖、界面背景、阅读背景、字体、字号字重、加载样式、圆角/玻璃强度。
2. **主题引擎与解析器**：把「配置 + 当前 ColorScheme」解析为具体 `Color/Font/资源 URL`，做非法值兜底与对比度校验，产出 `ThemeTokens`。
3. **主题状态与持久化层**：`AppStore` 内新增主题状态（沿用 `@MainActor @Observable`）；资产（图片/字体）落文件，配置本体进 `Snapshot` 新分区。
4. **环境注入层**：根部注入 `ThemeTokens`；各 sheet/fullScreenCover 必须像现有 `.appChrome(store)` 一样补注入。
5. **令牌适配层**：`Palette` 降级为「内置默认主题常量壳」；新代码统一用 `@Environment(\.theme)`；提供 `View+themeFont` 语义字体适配。
6. **自定义编辑器层**：实时预览 + 保存复用 + 导入导出 + 预设库（5 套阅读主题迁移为模板）+ MeshGradient 锚点编辑器。
7. **渲染器层**：`ThemeBackdrop`（静态）、`ThemedLoadingView`（统一所有 App 内加载态）。
8. **同步与包交换层**（本次决策新增）：`ThemePackage` 负责 `.yhthm` ZIP 打包解包与校验；`ThemeSyncService`（二期）负责 `YeHangThemeCatalog` 独立记录与冲突解决。

## 3. 核心数据结构（三份方案融合建议稿）

> 架构侧给出 `ThemeConfig` 主结构，持久化侧补充 `ThemeCatalog`（多主题 + 资产清单 + 继承 + 版本）。落地时以本节为融合基线：用持久化侧的 `ThemeColor`（双 hex + opacity，可 Codable）替换架构侧 `ColorSpec` 中的 hex 表达，其余保持架构侧语义枚举。

### 3.1 主题本体（架构侧）

```swift
struct ThemeConfig: Codable, Identifiable, Hashable, Sendable {
    var id: String
    var name: String
    var schemaVersion: Int = 1
    var colors: ColorRoles          // 与 Palette 一一对应的 13 个角色
    var uiBackground: BackgroundSpec
    var reader: ReaderBackgroundSpec
    var typography: TypographySpec
    var loading: LoadingStyleSpec
    var shape: ShapeSpec
}

enum ColorSpec: Codable, Hashable, Sendable {
    case system                     // 复用 Color.adaptive，系统明暗切换不重建视图
    case adaptive(light: UInt32, dark: UInt32,
                  lightOpacity: Double = 1, darkOpacity: Double = 1)
    case fixed(UInt32, opacity: Double = 1)
}

enum BackgroundSpec: Codable, Hashable, Sendable {
    case systemMesh                 // 现有 AppBackdrop 浅/深两套
    case solid(ColorSpec)
    case linear(colors: [ColorSpec], start: ThemePoint, end: ThemePoint)
    case radial(colors: [ColorSpec], center: ThemePoint,
                startRadius: Double, endRadius: Double)
    // 用户自定义 MeshGradient：静态锚点 + 配色，3×3~5×5，无时间/动画字段（见 §10.3）
    case mesh(points: [[Double]], colors: [ColorSpec])
    case image(asset: String, mode: ImageFillMode, overlay: ColorSpec?)
    // asset 为 Assets/Themes/<themeID>/ 下相对文件名，二进制不进 JSON
}

// 决策②：字体来源仅「系统字族」与「用户从文件 App 导入」，无 bundled 第三方字体
enum FontFamilySpec: Codable, Hashable, Sendable {
    case system(design: FontDesignSpec)                  // default/serif/rounded/monospaced
    case imported(assetID: String, postScriptName: String)
}

struct LoadingStyleSpec: Codable, Hashable, Sendable {
    enum Style: String, Codable { case spinner, brandMark, artwork, skeleton }
    var style: Style; var tint: ColorSpec
    var background: BackgroundSpec?   // nil = 跟随界面背景
    var title: String?; var artworkAsset: String?
    var respectReduceMotion: Bool = true
    var firstLaunchAnimation: Bool = false
}
```

### 3.2 可持久化颜色与目录（持久化侧）

```swift
struct ThemeColor: Codable, Equatable, Sendable {   // Color 不可 Codable，存 hex 双值
    var light: UInt32; var dark: UInt32
    var lightOpacity: Double = 1; var darkOpacity: Double = 1
    // init(from:) 用 decodeIfPresent ?? baseToken，opacity clamp 到 0...1
}

struct Theme: Codable, Identifiable, Equatable, Sendable {
    var id: String                   // UUID，稳定，不随改名变化
    var name: String
    var base: String?                // 继承的内置主题 id，nil = 从零开始
    var builtin: Bool = false
    var customized: Bool = false     // 内置主题是否被改过
    var builtinRevision: Int = 1
    var updatedAt: Date = Date()     // 决策①：二期冲突解决的时间戳依据
    var tokens: ThemeTokens; var typography: TypographySpec
    var backdrop: BackgroundSpec; var reading: ReadingSurfaceSpec
    var launch: LaunchSpec; var shape: ShapeSpec
    // init(from:) 逐字段兜底；解码后 resolve(base:) 展开继承与非法值
}

struct ThemeCatalog: Codable, Sendable {
    var schemaVersion: Int = 1
    var activeThemeID: String
    var themes: [Theme]; var assets: [AssetRef]
    var skippedThemes: [String]?     // 单个坏主题 id + 原因，不阻断整份 catalog
}

// 决策④：.yhthm 包内清单
struct ThemePackageManifest: Codable, Sendable {
    var format: String = "yhthm"
    var schemaVersion: Int = 1
    var themeID: String; var name: String
    var checksums: [String: String]  // 相对路径 → sha256，逐资产核对
    var createdAt: Date; var appVersion: String
}
```

**资产引用**：`AssetRef { id: String(sha256 前 32 hex), kind: .image/.font, ext: 白名单, byteCount, pixelSize? }`。引用一律只存 `assetID`，**绝不存绝对路径/URL**——解析时由 `assetURL(id)` 拼出，避免沙箱路径失效与 `../` 穿越。

### 3.3 解析令牌与阅读覆盖（环境注入用）

```swift
struct ThemeTokens: Equatable {
    var revision: Int                // 唯一比较依据：只比较 revision，避免 Color/Font 深比较
    var accent: Color                // ...其余色板角色
    var background: ResolvedBackground  // MeshGradient 的点/色数组在此一次性算好并缓存
    var reader: ResolvedReaderStyle
    var uiFont: FontRoleResolver     // (title/body/caption/...) -> Font
    var shape: ShapeSpec
    static func == (l, r: Self) -> Bool { l.revision == r.revision }
}

struct ReaderThemeOverride: Codable, Hashable, Sendable {
    var followGlobalTheme: Bool = true             // 默认跟随全局
    var preset: ReaderTheme? = nil                 // 保留 5 套作为 reader-only 模板
    var customReaderBackground: ReaderBackgroundSpec? = nil
    var fontFollowGlobal: Bool = true
    var fontDesign: ReaderFontDesign? = nil
    var fontWeight: ReaderWeight? = nil
}
```

## 4. 关键机制设计

### 4.1 动态令牌替换静态 `Palette`（渐进式迁移）

- 新增 `@Environment(\.theme) private var theme`，视图内用 `theme.accent`；`Palette` 保留为**内置默认主题常量壳**（标注 deprecated）。**不要**让 `Palette` 静态属性去读环境——SwiftUI 做不到。
- **迁移顺序（最重要）**：先迁移 `Theme.swift` 的共享组件（`GlassIconButton`/`SectionHeading`/`ProgressBar`/`RingProgress`/`BookCover`/`ToastView`/`SettingsRow`/`GlassSegmented`）与玻璃/背景 modifier。它们被所有页面复用，迁完大部分界面自动换肤，再逐文件清空直接引用。
- **默认参数陷阱**：`var tint: Color = Palette.accent` 这类默认值无法跟随环境，统一改为 `var tint: Color? = nil`，在 `body` 内 `let c = tint ?? theme.accent`。这是唯一需要改变调用语义处。
- **字体**：新增 `View+themeFont(_ role: FontRole)`（`.appTitle/.appBody/.appCaption/.readerBody`）；`ReaderTypography.fontName(for:)` 扩展接受已注册 PostScript 名。483 处 `.font(.system(size:))` 不一次替换：先按语义角色迁标题/正文/脚注，字面数值先作为 `uiScale` 乘数保留，观感零回归。
- **暗色自适应**：`ColorSpec.system` 继续走 `Color.adaptive`（`UIColor { traits in }` 动态 provider），系统明暗切换**不触发视图重建**；自定义主题由引擎按 `scheme` 解析，随 `appearance` 重注入一次。

### 4.2 主题变更最小化视图重建

- `ThemeTokens` 只比较 `revision`，令牌不变则不失效。
- 仿照 `SnapshotAutosaver`，新增 `ThemeApplicator` **零尺寸叶子**负责落盘与字体注册，绝不在 `RootView` 上 `onChange(of: theme)`。
- 阅读页 `rebuild()`（真 CoreText 重排）触发列表**不得加入纯颜色/背景变更**；只有全局主题导致阅读字体族真实变化时才显式 bump 一次 generation。
- 背景保持静态：`ThemeBackdrop` 仍禁止 `repeatForever`；网格点/颜色一次解析进 `ResolvedBackground` 缓存，30+ 处挂载从缓存读，不在 `body` 内重建；图片降采样缓存，沿用 `Color.clear.overlay + clipped + ignoresSafeArea`。首次换主题允许**一次** `withAnimation(.easeInOut)` 淡入。
- 编辑器用独立 `draft` 状态，拖色卡/拖网格点只刷预览容器；点「应用」才写 `AppStore.theme` 并 bump revision。

### 4.3 阅读主题与全局主题的继承/覆盖

优先级（高 → 低）：**阅读页显式覆盖 > 阅读页选中的内置预设 > 全局主题 > 内置默认主题**。

1. `followGlobalTheme == true`（默认）：阅读背景/文字/强调色取自全局 `reader`，换全局主题时阅读页随之变化。
2. 用户在阅读设置选 5 套预设之一或自定义背景 → 写 `preset`/`customReaderBackground` 并把 `followGlobalTheme` 置 false，该维度断开；提供「恢复跟随全局」翻回。
3. 字体独立：`fontFollowGlobal == true` 时字族跟随全局，但 `fontSize/lineSpacing` 仍归 `ReaderSettings`（符合已有心智）。
4. 5 套 `ReaderTheme` 迁移为 reader-only 模板，选中时写完整快照，向后兼容旧 `ReaderSnapshot`（新增 case 有 `try? decodeIfPresent` 兜底）。
5. 阅读页 `.preferredColorScheme` 取 `effective.isDark`，不再直接取 `settings.theme.isDark`。

### 4.4 冷启动首帧生效

- 现有 `AppStore.init()` 同步执行 `runLibraryMigration() → loadSnapshot()`；主题搭这班车，**同步**读，建议顺序 `loadThemeSynchronously() → runLibraryMigration() → loadSnapshot() → loadReadingRecords()`（主题读不依赖书库，放最前）。不用 `Task.detached`（会先闪默认色）。
- 同步读范围：只读 catalog JSON + 解码 + 校验（几十 KB / 几十毫秒），**不做图片/字体解码**；图片异步、首帧纯色占位，字体注册完刷新一次。
- `App.init()` 同步调用 `FontRegistry.registerAll()`：仅注册**用户从文件 App 导入**的字体（`.process` 作用域，每次启动重注册，不污染系统），失败按「自定义 → 系统 serif/system/rounded → 默认」回退，不阻塞启动（见 §10.2）。
- `WindowGroup` 根部在 `.environment(store)` 后立即注入 `.environment(\.theme, resolved)` 与 `.preferredColorScheme`，不在 `onAppear` 切换、不加过渡动画。
- 弹层扩展 `.appChrome(store)` 为 `.themedChrome(store)`：补回主题环境 + 明暗偏好 + 护眼层，**每个 sheet/fullScreenCover 都要接**。

### 4.5 加载画面可自定义的边界

| 场景 | 可否自定义 | 说明 |
|---|---|---|
| `UILaunchScreen`（Info.plist 空 dict） | **否** | 系统静态资源、运行时无 API、审核不允许伪装广告/交互。不承诺、不改。 |
| App 内加载态（阅读页 `isLoadingNetwork`、书源搜索、发现、漫画占位、同步/备份 busy 等） | **是** | 统一替换为 `ThemedLoadingView`，读 `theme.loading.style/tint/background/title`。替换点：ReaderView:464、SourceView:816、Labs:792、LibraryExtras:978、SettingsView:955 等。 |
| 首次进入动画 | **是（受限）** | 仅首次启动显示一次，约 0.6–0.9s，可跳过、尊重 Reduce Motion，用主题令牌绘制；不做成每启动都放的伪启动页。 |

新增 `View+themedLoading(isLoading:label:)`；`artwork` 用主题图片资产；动画元素限制在小尺寸控件，**不在背景层做无限循环**。

## 5. 可自定义维度全清单（设计系统 · 画意浓）

共 **5 大类、约 40 个维度**：

### 5.1 色彩类（对应 `Palette` 全部静态令牌）

`accent` / `accentSolid` / `onAccent` / `jade` / `gold` / `sand` / `blue` / `text` / `secondary` / `tertiary` / `hairline` / `faint` / `glassTint` / `covers[6]` / 数据分级色——保留「浅色/深色」成对定义（延续 `Color.adaptive`），每个令牌可独立取色，含透明度通道。`onAccent` 须与 `accent` 成对校验；封面改色须保证叠白字可读。

### 5.2 字体类

| 维度 | 现状/默认 | 决策后规格 |
|---|---|---|
| 阅读正文字族 | 宋体/系统/圆体，默认宋体 | 系统三档 + **仅用户从文件 App 导入的字体**（.ttf/.otf 注册后按 PostScript 名映射），带回退；**App 不内置任何第三方字体** |
| 界面字族 | 无（系统默认，写死 `.system`） | 系统默认 / 文件 App 导入；默认系统 |
| 标题字族 | 封面 `design:.serif`、环数字 `.rounded` | 系统字族 / 导入字体（同上） |
| 字号/字重/行距/版心 | 18pt / 三档 / 0.75 / 28·96·152pt | 滑杆 + 预设，支持 Dynamic Type 倍率 |
| 字符间距/段距 | 无（写死） | 新增 tracking 0…2pt、段距 0…8pt |

### 5.3 背景类

## 6. 持久化与版本兼容（持久化 · 库有方）

### 6.1 磁盘布局（新增 `Themes/`，与现有目录并列）

```
Application Support/YeHangChuan/Themes/
├── themes.json                  ← 目录/索引：schemaVersion + activeThemeID + themes + assets（提交点）
├── themes.prev.json             ← 上一版索引（仅当前可读时轮换）
├── themes.corrupt-<ts>.json     ← 坏文件留档
├── theme-decode-error.txt       ← 失败原因（含字段路径）
└── Assets/<sha256-32>.{png,heic,ttf,otf}   ← 内容寻址
```

**结论：主题本体独立文件，不并入 `library.json`**（避免索引膨胀、版本耦合、重演「一个字段坏整库读不出」）。

### 6.2 落盘规则

1. 内容寻址命名（sha256 前 32 hex + 白名单扩展名），引用只存 `assetID`，杜绝路径穿越。
2. 写入顺序：先资产 → 校验 → 再索引（对齐 `LibraryDocumentWriter`「先正文再索引，索引为提交点」）；索引写前轮转 `.prev.json`。
3. 原子写：资产 `.part` → 读回核对 sha256 → `.atomic` rename；索引 `.atomic + .sortedKeys`。
4. 孤儿清理：仅成功写入新 catalog 后，延迟一个启动周期、后台 utility 队列删除未引用资产。
5. 图片导入降采样到最长边 2048、>20MB 或 >6000px 拒绝；统一 `ThemeImageLoader` 降采样+缓存，避免 30+ 处各自解码 OOM。
6. 字体 ttf/otf 落 Assets/，`CTFontManagerRegisterFontsForURLs(.process)` 运行时注册，真实 PostScript 名写回 `ThemeFont.family`，失败降级提示（见 §10.2）。
7. 设置页「缓存占用」排除主题资产，单独展示「主题资产占用」。

### 6.3 版本兼容与迁移

三级版本：`ThemeCatalog.schemaVersion`（当前 1）、`Theme.builtinRevision`、`LibraryIndex.version`（不动）。沿用「逐字段兜底」惯例：新增字段给默认值、删除字段忽略旧键、改名字段 `case newName = "oldKey"` 接住再迁移、类型变更用中间 Decodable 包装、未知枚举只回退该项、数值 decode 后 clamp、数组限长、字符串限长。

`ThemeStore.bootstrap()`：读 `themes.json`→失败读 `.prev.json`；逐主题兜底（坏主题跳过记入 `skippedThemes`，不连带整份）；`schemaVersion < current` 串行幂等升级；`> current` 只读降级（**绝不写盘/留档**，对齐 `unsupportedVersion`）；文件损坏改名留档 + 记录原因 + 回落默认；未被改过的内置主题随 `builtinRevision` 更新。

**可回滚切换**（沿用凭据迁移范式）：`backend = .legacy | .dualWrite | .themeStore`。dualWrite 阶段旧字段继续写 + 影子写 ThemeStore，对账「令牌 == 旧 Palette 值」且「activeTheme 映射 == ReaderSettings.theme」，无差异后切 `.themeStore`；异常切回 `.legacy`，无需重启、不白屏。

### 6.4 与 Snapshot / 同步 / 备份的集成（决策①已落实）

- **Snapshot 桥接**：`AppStore.Snapshot` 仅加可选 `themeSelection`（`activeThemeID` + `catalogSchemaVersion`），缺则 nil 走 ThemeStore 自己。主题本体不随 Snapshot 走。
- **iCloud 一期**：只让 `activeThemeID` 随现有 Snapshot（CKAsset 快照）同步，指向内置主题即跨端一致；指向本机不存在的自定义 ID → 回退内置默认并提示，不静默。详见 §10.1。
- **iCloud 二期**：新增独立记录类型 `YeHangThemeCatalog`（每主题一条 CKRecord + CKAsset 资产），`updatedAt/deviceID` 冲突解决、本机优先 + 保留副本、墓碑删除、资产内容寻址去重，默认关闭。详见 §10.1。
- **备份：纳入 `.preferences` scope**。`BackupPayload` 加 `themeCatalog` + `themeAssets`（JSONEncoder 自动 base64），上限 20MB，超限只备份 catalog 并提示。恢复顺序：installAssets → replace(catalog) → 设 `themeSelection` → flush，只覆盖带了的字段。
- **边界划分**：`appearance` 仍决定 colorScheme；`EyeCareLayer` 是最后一层滤光，主题不重复实现；`ReaderSettings.theme` 与 `activeThemeID` 双向同步，**单一真相为 `activeThemeID`**。

### 6.5 导入安全（决策④已落实）

`.yhthm` 为 ZIP（内部 `manifest.json` + `theme.json` + `assets/`，见 §10.4）。校验：ZIP magic bytes + 扩展名双校验、manifest checksums 逐资产核对；解压炸弹防护（压缩比 >100、解压总量 >100MB 拒绝）；大小上限（theme.json 1MB / 单资产 10MB / 整包 50MB）；字段校验（hex 合法、alpha clamp、**网格点数=颜色数且 3×3~5×5**、导入字体名合法性）；路径只接受 assetID，拒绝 `../`/绝对路径/URL；**主题格式不支持任何可执行脚本**；字体资产导入仍需版权确认；大图解码放 `Task.detached(.utility)`；一键恢复默认前留 `.bak` + 5 秒撤销；主题写也走 sequence 防旧覆盖（200ms 合并、进后台 flush）。

## 10. 已确认决策与细化规格（本次更新重点）

> 以下 4 项由用户于 2026-11-28 确认，已从「开放项」转为「设计决策」，并细化到可实施规格。

### 10.1 决策①：iCloud 主题同步

**已定路线**：一期只同步 `activeThemeID`；自定义主题跨端放到二期，用独立记录 + 冲突解决。

#### 一期（随现有 Snapshot）

- **载体**：`AppStore.Snapshot.themeSelection.activeThemeID` 随 `CloudSyncService.exportedSnapshotData()` / `importSnapshotData` 走现有单条 CKRecord `YeHangSnapshot`（CKAsset），**不新增记录类型**。
- **生效规则**：
  - 指向内置主题 ID → 两端都有，直接生效。
  - 指向自定义主题 ID 但本机 catalog 无此 ID → **回退内置默认主题** + 一次性提示「此主题在本机不存在，已回退默认；请导入 `.yhthm` 或开启二期同步」。不静默、不白屏。
- **合并策略**：沿用 `CloudSyncService` 本机优先；`themeSelection` 在 `Snapshot` 里按现有 scope 机制合并，缺字段走 `decodeIfPresent` 兜底为 nil。
- **验收**：两台设备切换主题后拉取，另一端主题一致；指向不存在的 ID 时回退并提示。

#### 二期（独立记录 + 冲突解决）

- **开关**：功能实验室「主题 iCloud 同步」，**默认关闭**；开启时请求 CloudKit 权限，未登录/拒绝则关闭同步并如实提示（对齐现有 iCloud 行为）。
- **记录类型**：新增 `YeHangThemeCatalog`，**每个自定义主题一条 CKRecord**：
  | 字段 | 类型 | 用途 |
  |---|---|---|
  | `themeID` | String | 主键，稳定 ID |
  | `name` | String | 展示名 |
  | `schemaVersion` | Int | 格式版本 |
  | `updatedAt` | Date | 冲突判定依据 |
  | `deviceID` | String | 冲突判定依据 |
  | `payload` | CKAsset | `theme.json` |
  | `assets` | [CKAsset] | 字体/图片，按 assetID 内容寻址 |
- **上传**：`ThemeSyncService.push(theme)` — 先按 assetID 去重上传资产（远端已有则跳过）→ 上传 payload → 写记录，带 `updatedAt/deviceID`。
- **下载**：`pull()` — 查询全部记录 → 逐条比对本地 `themeID`：
  - 本地无 → 资产落地 → 解码 → 预览可用后安装。
  - 本地有且远端 `updatedAt > 本地` → **冲突**，进入解决流程。
  - 本地有且远端 `updatedAt <= 本地` → 跳过（本机优先）。
- **冲突解决（用户三选一，不静默覆盖）**：
  1. **保留本机**（默认）：丢弃远端版本。
  2. **采用远端**：用远端替换本机（先落地资产，校验通过才替换）。
  3. **保留两份**：远端主题重命名为「原名（来自〈设备名〉）」、分配新 ID 后安装，与本机并存。
  - UI：设置 → 主题 → 同步详情，列出冲突项，显示双方修改时间与缩略预览，逐项选择。
- **删除同步**：用**墓碑**（记录加 `deletedAt`），拉取见墓碑则本地删除；墓碑保留 30 天后清理，避免硬删导致另一端重新上传。
- **容量与失败兜底**：单主题 payload < 1MB、单资产 < 10MB、整主题 < 50MB；超限提示改用 `.yhthm` 手动导出。CloudKit 不可用时不影响本机主题。
- **与一期共存**：一期 `activeThemeID` 仍走 Snapshot；二期主题本体走独立记录；两者互不冲突。

### 10.2 决策②：字体来源——仅用户从文件 App 导入

**已定路线**：App 不内置任何第三方字体；系统字族之外的字体只能由用户从文件 App 导入。

- **来源剥离**：`FontFamilySpec` 只保留 `.system(design)` 与 `.imported(assetID, postScriptName)`，移除持久化草案里的 `.bundled`；`ThemeFont.Source = .system/.imported`。系统字族（serif / default / rounded / monospaced）不算第三方字体。
- **导入入口**：SwiftUI `.fileImporter`，UTI 为 `public.truetype-ttf-font` / `public.opentype-font` / `public.truetype-font` 等；也接受从 `.yhthm` 包内带入的字体资产（见下方说明）。
- **校验**：magic bytes（`0x00010000` / `OTTO` / `true` / `ttcf`）+ 扩展名双校验；单文件 ≤ 10MB；注册前先落 Assets/ 并核对 sha256。
- **注册**：`CTFontManagerRegisterFontsForURLs([url], .process)` — 每次启动重注册，作用域为进程，**不持久化到系统、不污染系统字体库**。`CTFontCopyPostScriptName` 提取真实名字写回 `ThemeFont.family`。
- **CoreText 对齐**：阅读页 CoreText 排版与 SwiftUI `Font.custom(_, size:)` 使用同一个 PostScript 名，避免「SwiftUI 显示一种字、CoreText 排另一种」。
- **回退链**：注册失败 / 缺字 → 该角色的系统 design（serif / default / rounded）→ 默认字体，不空白、不崩溃。
- **版权确认**：导入前一次性提示「请确认你拥有该字体的合法使用授权」，确认状态记录，不重复弹窗。
- **与 `.yhthm` 的关系（重要澄清）**：决策④的包内可含字体资产，这是**用户自有字体的跨端迁移**，不属于 App 内置字体；另一端导入包内字体时仍需版权确认。两者不矛盾。

### 10.3 决策③：开放 MeshGradient 自定义点

**已定路线**：开放用户自定义 MeshGradient 的锚点与配色，但严格保持静态。

- **数据结构**（沿用 `BackgroundSpec.case mesh`）：
  - 网格 `rows, cols ∈ 3...5`（默认 3×3，对齐现有 `AppBackdrop`）。
  - `points.count == rows × cols`、`colors.count == points.count`，否则解码回退 `systemMesh`（逐字段兜底惯例）。
  - 每点 `[x, y]` clamp 到 `0...1`；**边缘点固定在边界**（x=0/1 或 y=0/1，SwiftUI MeshGradient 的约束），内部点可自由拖拽。
  - 颜色为 `ThemeColor`（浅/深双 hex），随系统明暗切换。
- **静态硬约束**：结构中**不得出现任何时间/速度/相位字段**；渲染器禁用 `repeatForever`；编辑器不提供动画开关。用户改的是「锚点位置 + 颜色」，得到的是一张静态网格渐变。
- **解析与缓存**：`ThemeEngine.resolve(background:)` 一次性生成 `ResolvedBackground`（points/colors 数组算好），30+ 处 `ThemeBackdrop` 从缓存读，**不在 `body` 内重建**；首次换主题允许一次 `withAnimation(.easeInOut)` 淡入。
- **编辑器**：网格点可视化拖拽 + 每点取色 + 预设网格模板（沿现有夜色水面）；实时预览（390×844）；草稿隔离（拖点时只刷预览，点「应用」才 bump revision）。
- **性能护栏**：5×5 上限；不叠加多个 mesh；光斑 ≤ 3 且静态；离屏渲染成本用 Instruments 验证切页/弹层/滚动无掉帧。
- **可读性护栏**：网格色与文字令牌做最坏对比度校验，过曝/过暗区域即时提示「一键修正」。

### 10.4 决策④：主题文件格式 `.yhthm`（ZIP 含资产）

**已定路线**：`.yhthm` 为 ZIP 容器，含清单、主题本体与资产。

```
theme.yhthm  (ZIP)
├── manifest.json     ← format:"yhthm", schemaVersion, themeID, name, checksums, createdAt, appVersion
├── theme.json        ← Theme / ThemeConfig（Codable，逐字段兜底）
└── assets/
    ├── <sha256-32>.png / .heic   ← 图片背景、加载画面 artwork
    └── <sha256-32>.ttf / .otf    ← 用户导入字体（跨端迁移，见 §10.2）
```

- **导出**：`ShareLink(item: packageURL)`；打包时先算每个资产 sha256 写入 `manifest.checksums`，再压缩为 `.yhthm`。
- **导入流水线**：`.fileImporter`（`public.zip-archive`）→ magic bytes + 扩展名双校验 → 解压到临时目录（防 bomb：压缩比 >100 / 解压总量 >100MB 拒绝）→ 按 `checksums` 逐资产核对 → `theme.json` 逐字段兜底解码 + 网格点数/字体合法性校验 → 资产落盘（sha256 命名，已存在则跳过）→ 预览确认 → 保存。
- **ID 冲突**：导入主题 ID 与本地相同 → 分配新 ID + 保留两份，不静默覆盖。
- **大小上限**：整包 ≤ 50MB、单资产 ≤ 10MB、`theme.json` ≤ 1MB；超限拒绝并提示改用逐项设置。
- **版本**：`manifest.schemaVersion > 当前` → 只读预览、不导入（对齐「未来版本只读」原则）。
- **安全**：字体资产导入仍需版权确认；所有解压/校验/解码在 `Task.detached(.utility)` 完成，不在 UI 线程，也不含任何可执行脚本。
